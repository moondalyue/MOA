## 1. 목표와 요구사항

일반 사용자가 MOA에 이메일과 비밀번호로 가입하고, 이메일 소유 확인을 마친 뒤 계정을 사용할 수 있게 한다. 실제 계정 저장, 이메일 인증, 운영용 메일 설정을 포함한다.

## 2. 포함·제외 범위

### 포함

- 이름, 이메일, 비밀번호, 비밀번호 확인 입력 화면
- 계정 생성과 이메일 인증 안내·재발송
- 이메일 인증 완료·만료·실패 처리
- 가입 후 사용에 필요한 최소 로그인·로그아웃
- 공개 서비스의 계정 복구를 위한 비밀번호 재설정
- SMTP·발신 도메인·인증 주소 설정 안내와 연결
- 모바일·키보드 사용, 오류·처리 중 상태
- 설정 문서와 실제 검증 결과 기록
- Vercel을 배포 대상으로 하는 구현과 설정 안내

### 제외

- 소셜 로그인, 관리자 기능, 회원 정보 관리 화면
- 기존 앱 데이터의 계정 연결·이관
- 별도 승인 없는 실제 배포, Git 작업, 유료 서비스 결제

## 3. 화면·사용 흐름

- `/signup`: 가입 정보 입력 → 인증 메일 확인 안내
- 메일 인증 링크: 안전하게 검증 → 완료 또는 재시도 안내
- `/login`: 인증을 마친 계정으로 로그인
- `/account`: 본인의 로그인 상태 확인·로그아웃
- `/forgot-password`: 재설정 메일 요청
- `/reset-password`: 유효한 복구 절차를 거쳐 비밀번호 변경

모바일은 한 열로 구성하고 입력 라벨·오류·포커스를 제공한다. 중복 제출을 막고 실패 시 비밀번호를 저장하거나 기록하지 않는다. 기존 폰트와 첫 화면은 유지한다.

KRDS는 입력 안내·오류·키보드 사용 원칙을 선택적으로 참고한다. 공식 입력폼 가이드 v0.4를 확인 기준으로 삼으며 정부 식별 요소와 전체 스타일 복사는 제외한다. 전체 준수나 인증 완료로 표현하지 않는다.

- 공식 참고: https://v04.krds.go.kr/guide/global/global_08.html

## 4. 현재 구조와 구현 방향

### 기존 코드·설정

- Next.js 16.4.3, React 19, Prisma 7 구성
- 기본 `User` 모델은 있지만 인증·세션 연동은 없음
- 관련 기능 계획과 미완료 코드 변경은 없음
- `node_modules`가 없어 구현 검증 전에 의존성 설치 필요
- 현재 Node.js는 v24.22.1이며 package.json의 24.x 요구와 일치
- 현재 `cacheComponents`, `partialPrefetching`, Prisma 연결 설정 유지

### DB 분석과 저장

- Supabase Auth를 계정 정보의 기준으로 사용한다.
- 이름은 인증 계정의 사용자 메타데이터에 저장한다.
- 기존 앱용 `users` 테이블은 이번 기능에서 사용하지 않는다.
- 이메일 주소만으로 기존 앱 회원과 자동 연결하지 않는다.
- 이번 범위에는 Prisma 모델 변경·마이그레이션이 필요 없다.
- 기존 데이터 삭제·이관은 하지 않는다. 백업·복구 작업은 이번 범위에 해당하지 않는다.
- 실제 계정 저장과 메일 발송은 대상 프로젝트와 테스트 계정을 확인한 뒤 검증한다.

### 서버·입력 검증·권한

- 화면과 서버에서 입력을 각각 검사한다.
- 이름·이메일의 길이와 형식, 비밀번호 규칙을 정한다.
- 비밀번호는 임의로 공백을 제거하거나 변환하지 않는다.
- 화면·서버·Supabase의 비밀번호 정책을 일치시킨다.
- Supabase의 비밀번호·토큰 관리를 사용한다.
- 이메일 확인 전 서비스 이용을 허용하지 않는다.
- 쿠키 기반 세션과 서버의 사용자 확인을 구현한다.
- 사용자별 응답을 공용 캐시에 저장하지 않는다.
- 인증 링크의 유형·만료·이동 주소를 검사한다.
- 계정 존재 여부와 내부 오류를 과도하게 공개하지 않는다.
- 메일 재발송 제한과 자동 가입 방지 설정을 검토·연결한다.
- 관리자 키, 비밀번호, 인증 토큰을 코드·로그에 남기지 않는다.
- 공통 형식 검사는 작은 스키마로 공유하고 서버 인증 판단과 분리한다.
- 필드별 오류와 폼 전체 오류를 구분하고 재시도 경로를 제공한다.

### 화면·폰트·재사용

- 기본 폰트 설정을 유지하고 한글 대체 글꼴과 모바일 줄바꿈을 확인한다.
- 실제 반복되는 입력·상태 UI만 공유하며 범용 계층을 미리 만들지 않는다.
- Server Component를 기본으로 하고 폼 상호작용에 필요한 부분만 Client Component로 구현한다.

### 외부 설정과 위험

- 대상 Supabase 프로젝트 확인
- SMTP 서비스와 발신 주소·도메인 인증: 아직 준비되지 않음. 설정 방법 안내 필요
- 이메일 인증 활성화와 인증·복구 메일 템플릿
- 로컬·운영 주소 및 허용 리디렉션
- Vercel 선택 완료. 실제 Vercel 배포 주소는 아직 미정
- 기존에 제시한 GitHub Pages 주소는 이번 서버 인증 구현의 배포 대상으로 사용하지 않음
- 발송 제한과 자동 가입 방지 설정
- 실제 비밀값은 서비스 설정 화면 또는 환경 파일에서 관리
- 메일·DNS·배포 설정이 준비되기 전에는 공개 서비스 인증 검증을 완료로 표시하지 않음

### 협업·중복 검토

- 현재 `main` 브랜치의 코드와 `plans/`를 확인했다.
- 기존 폼 도구와 DB 연결 구성을 재사용한다.
- 새 앱용 회원 테이블이나 중복 비밀번호 저장소는 만들지 않는다.
- 다른 브랜치·팀원의 미공유 작업은 확인하지 못했다.
- 현재 확인 범위에서 공통 파일의 동시 수정은 발견되지 않았다.
- 겹침이 새로 확인되면 해당 부분의 영향과 반영 순서를 조정한다.

### `src/lib/auth-validation.ts`

화면과 서버가 공유하는 입력 규칙·결과 형식

```ts
import { z } from 'zod';

export const authModeSchema = z.enum([
  'signup',
  'login',
  'forgot',
  'reset',
  'resend',
]);
export type AuthMode = z.infer<typeof authModeSchema>;
export const emailSchema = z.email('이메일 주소를 확인해 주세요.').max(254);
export const passwordSchema = z
  .string()
  .min(12, '비밀번호는 12자 이상 입력해 주세요.')
  .max(128, '비밀번호는 128자 이하로 입력해 주세요.');

export function authSchema(mode: AuthMode) {
  return z
    .strictObject({
      name: z.string().max(80, '이름은 80자 이하로 입력해 주세요.'),
      email: z.string().max(254, '이메일은 254자 이하로 입력해 주세요.'),
      password: z.string().max(128, '비밀번호는 128자 이하로 입력해 주세요.'),
      confirmPassword: z.string().max(128),
      captchaToken: z.string().max(2048),
    })
    .superRefine((value, context) => {
      if (mode === 'signup' && !value.name.trim()) {
        context.addIssue({
          code: 'custom',
          path: ['name'],
          message: '이름을 입력해 주세요.',
        });
      }
      if (
        mode !== 'reset' &&
        !emailSchema.safeParse(value.email.trim()).success
      ) {
        context.addIssue({
          code: 'custom',
          path: ['email'],
          message: '이메일 주소를 확인해 주세요.',
        });
      }
      if (mode === 'login' && !value.password) {
        context.addIssue({
          code: 'custom',
          path: ['password'],
          message: '비밀번호를 입력해 주세요.',
        });
      }
      if (mode === 'signup' || mode === 'reset') {
        const result = passwordSchema.safeParse(value.password);
        if (!result.success) {
          context.addIssue({
            code: 'custom',
            path: ['password'],
            message: result.error.issues[0].message,
          });
        }
        if (value.password !== value.confirmPassword) {
          context.addIssue({
            code: 'custom',
            path: ['confirmPassword'],
            message: '비밀번호가 일치하지 않습니다.',
          });
        }
      }
    });
}

export type AuthValues = z.infer<ReturnType<typeof authSchema>>;
export type AuthResult = {
  status: 'success' | 'error';
  message: string;
  fieldErrors?: Partial<Record<keyof AuthValues, string[]>>;
  destination?: '/account' | '/login';
};

export const confirmationSchema = z.strictObject({
  tokenHash: z
    .string()
    .regex(/^[a-zA-Z0-9_-]{16,256}$/, '인증 링크를 확인해 주세요.'),
  type: z.enum(['email', 'recovery']),
});
```

```ts
import 'server-only';
import { z } from 'zod';

const schema = z.object({
  url: z.url().refine((value) => {
    const url = new URL(value);
    return url.protocol === 'https:' && !url.username && !url.password;
  }),
  key: z.string().startsWith('sb_publishable_'),
  siteUrl: z.url().refine((value) => {
    const url = new URL(value);
    const local = ['localhost', '127.0.0.1'].includes(url.hostname);
    return (
      (url.protocol === 'https:' || (local && url.protocol === 'http:')) &&
      !url.username &&
      !url.password &&
      !url.search &&
      !url.hash &&
      url.pathname === '/'
    );
  }),
});

export function getAuthConfig() {
  const result = schema.safeParse({
    url: process.env.NEXT_PUBLIC_SUPABASE_URL,
    key: process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY,
    siteUrl: process.env.SITE_URL,
  });
  if (!result.success)
    throw new Error('Authentication configuration is unavailable.');
  return { ...result.data, siteUrl: new URL(result.data.siteUrl).origin };
}

  return {
    path: '/',
    sameSite: 'lax' as const,
    secure: process.env.SITE_URL?.startsWith('https://') === true,
```

### `src/lib/supabase/server.ts`

요청별 인증 클라이언트; 화면은 쿠키 읽기, 서버 처리는 쓰기

```ts
import 'server-only';
import { createServerClient } from '@supabase/ssr';
import { cookies } from 'next/headers';
import { authCookieOptions, getAuthConfig } from './config';

export async function createAuthClient(writable = false) {
  const config = getAuthConfig();
  const store = await cookies();
  return createServerClient(config.url, config.key, {
    cookieOptions: authCookieOptions(),
    cookies: {
      getAll: () => store.getAll(),
      setAll(values) {
        // Server Components cannot write cookies. Proxy refreshes them first.
        if (!writable) return;
        values.forEach(({ name, value, options }) => {
          store.set(name, value, { ...options, ...authCookieOptions() });
        });
      },
    },
  });
}
```

### `src/proxy.ts`

인증 경로의 세션 갱신·비공개 응답 헤더; 권한 검사는 각 서버 처리에서 반복

```ts
import { createServerClient } from '@supabase/ssr';
import { NextResponse, type NextRequest } from 'next/server';
import { authCookieOptions, getAuthConfig } from '@/lib/supabase/config';

export async function proxy(request: NextRequest) {
  let response = NextResponse.next({ request });
  const protectHeaders = () => {
    response.headers.set('Cache-Control', 'private, no-store, max-age=0');
    response.headers.set('Pragma', 'no-cache');
    response.headers.set('Expires', '0');
    response.headers.set('Referrer-Policy', 'no-referrer');
    response.headers.set('X-Robots-Tag', 'noindex, nofollow');
  };
  protectHeaders();
  try {
    const config = getAuthConfig();
    const client = createServerClient(config.url, config.key, {
      cookieOptions: authCookieOptions(),
      cookies: {
        getAll: () => request.cookies.getAll(),
        setAll(values, headers) {
          values.forEach(({ name, value }) => request.cookies.set(name, value));
          response = NextResponse.next({ request });
          values.forEach(({ name, value, options }) => {
            response.cookies.set(name, value, {
              ...options,
              ...authCookieOptions(),
            });
          });
          Object.entries(headers ?? {}).forEach(([name, value]) =>
            response.headers.set(name, value),
          );
          protectHeaders();
        },
      },
    });
    await client.auth.getClaims();
  } catch {
    // Protected pages and actions verify the user independently and fail closed.
    console.error('[auth:session] refresh_unavailable');
  }
  return response;
}

export const config = {
  matcher: [
    '/signup',
    '/login',
    '/forgot-password',
    '/reset-password',
    '/account/:path*',
    '/auth/:path*',
  ],
};
```

```ts
  authModeSchema,
  authSchema,
  confirmationSchema,
  type AuthResult,
} from '@/lib/auth-validation';
import { getAuthConfig } from '@/lib/supabase/config';
import { createAuthClient } from '@/lib/supabase/server';

const unavailable =
  '지금은 요청을 처리할 수 없습니다. 잠시 후 다시 시도해 주세요.';
const mailMessage =
  '입력한 주소로 안내할 수 있는 경우 메일을 보냈습니다. 받은편지함과 스팸함을 확인해 주세요.';

export async function submitAuth(
  modeInput: unknown,
  input: unknown,
): Promise<AuthResult> {
  const parsedMode = authModeSchema.safeParse(modeInput);
  if (!parsedMode.success)
    return { status: 'error', message: '요청을 확인해 주세요.' };
  const mode = parsedMode.data;
  const parsed = authSchema(mode).safeParse(input);
  if (!parsed.success) {
    return {
      status: 'error',
      message: '입력한 내용을 확인해 주세요.',
      fieldErrors: z.flattenError(parsed.error).fieldErrors,
    };
  }
  const values = parsed.data;
  try {
    const captchaRequired =
      mode !== 'reset' &&
      (process.env.NODE_ENV === 'production' ||
        Boolean(process.env.NEXT_PUBLIC_TURNSTILE_SITE_KEY));
    if (captchaRequired && !values.captchaToken) {
      return {
        status: 'error',
        message: '자동 입력 방지 확인을 완료해 주세요.',
      };
    }
    if (captchaRequired && !process.env.NEXT_PUBLIC_TURNSTILE_SITE_KEY) {
      console.error('[auth:submit] captcha_configuration_missing');
      return { status: 'error', message: unavailable };
    }
    const config = getAuthConfig();
    const client = await createAuthClient(true);
    const email = values.email.trim();
    const redirectTo = `${config.siteUrl}/auth/confirm`;
    const captchaToken = values.captchaToken || undefined;
    let error: { code?: string; status?: number } | null = null;

    if (mode === 'signup') {
      const result = await client.auth.signUp({
        email,
        password: values.password,
        options: {
          data: { name: values.name.trim() },
          emailRedirectTo: redirectTo,
          captchaToken,
        },
      });
      error = result.error;
      if (!error && result.data.session) {
        await client.auth.signOut({ scope: 'local' });
        console.error('[auth:signup] email_confirmation_disabled');
        return { status: 'error', message: unavailable };
      }
      if (error?.code === 'user_already_exists') error = null;
    } else if (mode === 'login') {
      const result = await client.auth.signInWithPassword({
        email,
        password: values.password,
        options: { captchaToken },
      });
      if (result.error || !result.data.user?.email_confirmed_at) {
        if (result.data.session) await client.auth.signOut({ scope: 'local' });
        return {
          status: 'error',
          message:
            '로그인 정보를 확인해 주세요. 가입 후 이메일 인증도 완료해야 합니다.',
        };
      }
      return {
        status: 'success',
        message: '로그인했습니다.',
        destination: '/account',
      };
    } else if (mode === 'forgot') {
      const result = await client.auth.resetPasswordForEmail(email, {
        redirectTo,
        captchaToken,
      });
      error = result.error;
    } else if (mode === 'resend') {
      const result = await client.auth.resend({
        type: 'signup',
        email,
        options: { emailRedirectTo: redirectTo, captchaToken },
      });
      error = result.error;
    } else {
      const { data, error: userError } = await client.auth.getUser();
      if (userError || !data.user?.email_confirmed_at) {
        return {
          status: 'error',
          message: '비밀번호 재설정 메일을 다시 요청해 주세요.',
        };
      }
      const result = await client.auth.updateUser({
        password: values.password,
      });
      error = result.error;
      if (!error) {
        const signOut = await client.auth.signOut({ scope: 'global' });
        if (signOut.error) {
          console.error('[auth:reset] session_revocation_failed');
          return {
            status: 'success',
            message:
              '비밀번호를 변경했습니다. 계정 화면에서 로그아웃해 주세요.',
          };
        }
        return {
          status: 'success',
          message: '비밀번호를 변경했습니다. 새 비밀번호로 로그인해 주세요.',
        };
      }
    }
    if (error) {
      if (error.status === 429 || error.code?.startsWith('over_')) {
        return {
          status: 'error',
          message: '요청이 많습니다. 잠시 기다린 뒤 다시 시도해 주세요.',
        };
      }
      if (error.code === 'captcha_failed') {
        return {
          status: 'error',
          message: '자동 입력 방지 확인을 다시 진행해 주세요.',
        };
      }
      if (error.code === 'weak_password' || error.code === 'same_password') {
        return {
          status: 'error',
          message: '다른 안전한 비밀번호를 사용해 주세요.',
        };
      }
      console.error('[auth:submit] provider_request_failed');
      return { status: 'error', message: unavailable };
    }
    return { status: 'success', message: mailMessage };
  } catch {
    console.error('[auth:submit] unavailable');
    return { status: 'error', message: unavailable };
  }
}

export async function confirmEmail(formData: FormData) {
  const parsed = confirmationSchema.safeParse({
    tokenHash: formData.get('tokenHash'),
    type: formData.get('type'),
  });
  if (!parsed.success) redirect('/auth/error');
  let destination = '/auth/error';
  try {
    const client = await createAuthClient(true);
    const { data, error } = await client.auth.verifyOtp({
      token_hash: parsed.data.tokenHash,
      type: parsed.data.type,
    });
    if (!error && data.user?.email_confirmed_at && data.session) {
      destination =
        parsed.data.type === 'recovery' ? '/reset-password' : '/account';
    }
  } catch {
    console.error('[auth:confirm] unavailable');
  }
  redirect(destination);
}

export async function logout() {
  let failed = false;
  try {
    const client = await createAuthClient(true);
    const { error } = await client.auth.signOut({ scope: 'local' });
    failed = Boolean(error);
  } catch {
    failed = true;
    console.error('[auth:logout] unavailable');
  }
  redirect(failed ? '/auth/error' : '/login');
}
```

```tsx
'use client';

import Script from 'next/script';
import { useEffect, useRef, useState } from 'react';

type TurnstileApi = {
  render: (
    container: HTMLElement,
    options: {
      sitekey: string;
      size: 'compact';
      callback: (token: string) => void;
      'expired-callback': () => void;
      'error-callback': () => void;
    },
  ) => string;
  remove: (id: string) => void;
};

declare global {
  interface Window {
    turnstile?: TurnstileApi;
  }
}

export function Turnstile({ onToken }: { onToken: (token: string) => void }) {
  const sitekey = process.env.NEXT_PUBLIC_TURNSTILE_SITE_KEY;
  const container = useRef<HTMLDivElement>(null);
  const [ready, setReady] = useState(false);
  const [failed, setFailed] = useState(false);
  const [attempt, setAttempt] = useState(0);

  useEffect(() => {
    const api = window.turnstile;
    if (!sitekey || !ready || !api || !container.current) return;
    const id = api.render(container.current, {
      sitekey,
      size: 'compact',
      callback: (token) => {
        setFailed(false);
        onToken(token);
      },
      'expired-callback': () => onToken(''),
      'error-callback': () => {
        setFailed(true);
        onToken('');
      },
    });
    return () => api.remove(id);
  }, [ready, sitekey, onToken, attempt]);

  if (!sitekey) return null;
  return (
    <div className="space-y-2">
      <Script
        src="https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit"
        onReady={() => setReady(true)}
        onError={() => {
          setFailed(true);
          onToken('');
        }}
      />
      <div ref={container} aria-label="자동 입력 방지 확인" />
      {failed && (
        <p role="alert" className="text-sm text-red-700 dark:text-red-300">
          자동 입력 방지 확인을 불러오지 못했습니다.{' '}
          <button
            type="button"
            className="underline"
            onClick={() => {
              setFailed(false);
              onToken('');
              if (window.turnstile) setAttempt((value) => value + 1);
              else window.location.reload();
            }}
          >
            다시 시도
          </button>
        </p>
      )}
    </div>
  );
}
```

```tsx
  );
}
```

```ts
        password,
        confirmPassword: password,
      }).success,
      true,
    );
  }

    { ...valid, role: 'admin' },
    { email: valid.email },
    { ...valid, captchaToken: 'x'.repeat(2049) },

  ])
```

+6. 설정 후 서버를 재시작합니다. Auth만 사용하는 이번 기능에는 Prisma 마이그레이션이나 앱용 `users` 테이블이 필요하지 않습니다.
+
+### 2. 발신 도메인과 SMTP
+
+1. 본인이 관리하는 발신 도메인과 인증 메일용 주소를 준비합니다. Vercel에서 받은 `vercel.app` 주소를 메일 발신 도메인으로 소유한 것으로 간주하지 않습니다.
+2. SMTP를 제공하는 메일 발송 서비스를 선택합니다. 계정 생성·도메인 구매·유료 결제는 대상과 비용을 확인한 뒤 진행합니다.
+3. 해당 서비스가 발급한 DNS 레코드를 도메인 관리 화면에 등록하고 발신 도메인의 인증 완료를 확인합니다. 임의의 DNS 값을 만들어 넣지 않습니다.
+4. Supabase Authentication의 SMTP 설정에 발신자명·발신 주소·SMTP 호스트·포트·사용자명·비밀번호를 입력합니다. 비밀번호/API 키는 이 설정 화면에서 관리하며 앱의 공개 환경 변수에 넣지 않습니다.
+5. 발송 제한을 설정하고 메일 본문의 링크 추적 기능은 끕니다. 링크를 자동 변경하거나 소비하는 설정을 피합니다.
+6. 승인된 확인용 주소로 실제 인증·복구 메일 수신, 스팸함, 발신자 표시를 확인합니다. 기본 SMTP의 제한을 일반 사용자용 운영 설정으로 대신하지 않습니다.
+
+### 3. 인증 주소와 메일 템플릿
+
+- 로컬 개발 프로젝트의 Site URL은 `http://localhost:3000`, 운영 프로젝트는 실제 Vercel HTTPS 주소로 지정합니다.
+- 각 환경의 `/auth/confirm` 전체 주소를 Redirect URLs에 정확히 허용합니다. 운영에 무제한 와일드카드나 임의 사용자 입력 주소를 허용하지 않습니다.
+- Confirm signup 템플릿의 본문은 다음과 같이 설정합니다.
+
+```html
+<h2>MOA 이메일 인증</h2>
+<p>직접 가입을 요청했다면 아래 링크에서 인증을 완료해 주세요.</p>
+<p><a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=email">이메일 인증 계속하기</a></p>
+<p>요청하지 않았다면 이 메일을 무시해 주세요.</p>
+```
+
+- Reset password 템플릿은 다음과 같이 설정합니다.
+
+```html
+<h2>MOA 비밀번호 재설정</h2>
+<p>직접 요청했다면 아래 링크에서 새 비밀번호를 설정해 주세요.</p>
+<p><a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=recovery">비밀번호 재설정 계속하기</a></p>
+<p>요청하지 않았다면 이 메일을 무시해 주세요.</p>
+```
+
+앱의 가입·재발송·복구 요청은 고정된 `SITE_URL`을 사용합니다. 링크의 임의 `next` 주소는 사용하지 않습니다. 템플릿 저장만으로 실제 인증이 검증된 것은 아닙니다.
+
+### 4. 자동 가입 방지·재발송 제한
+
+1. Cloudflare Turnstile 위젯을 준비하고 사용할 로컬·실제 Vercel 호스트를 등록합니다.
+2. 공개 Site key를 `NEXT_PUBLIC_TURNSTILE_SITE_KEY`에 넣고 Secret key는 Supabase CAPTCHA 설정에 넣습니다.
+3. Supabase에서 Turnstile CAPTCHA를 활성화하고 가입·로그인·복구 폼의 성공·만료·실패를 확인합니다.
+4. 메일 재발송·로그인·가입의 Supabase 요청 제한과 발송 서비스 한도를 확인합니다. 앱의 제출 버튼 비활성화는 서버 요청 제한의 대체가 아닙니다.
+5. 개발 중 Site key를 비워 둔 경우는 위젯 없는 로컬 확인에 한합니다. 공개 빌드에서는 키가 필요합니다. CAPTCHA·SMTP가 미설정이면 공개 준비 완료로 표시하지 않습니다.
+6. 서버에서 Supabase를 호출하므로 IP 기반 제한이 서버의 외부 IP에 집계될 수 있습니다. 실제 트래픽과 제한 응답을 확인하고 필요 시 별도 제한 설계를 검토합니다. 관리자 키를 이용한 IP 전달을 임의로 추가하지 않습니다.
+
+### 5. 검사와 공개 전 확인
+
+- `node --import tsx --test scripts/auth-validation.test.ts`: 입력·해시·유형·추가 필드 검사. 실제 인증·메일 검사를 대신하지 않습니다.

+- 복구 링크·새 비밀번호·기존 세션 폐기·로그아웃과 다른 계정 정보 접근 차단을 확인합니다. 액세스 토큰의 즉시 폐기를 무조건 보장하지 않으며 서비스의 토큰 만료·회수 동작도 확인합니다.
+- 모바일·키보드·포커스·확대·대비·라이트/다크 표시를 브라우저에서 확인합니다.
+- Vercel 배포 후 실제 주소에서 다시 검사합니다. GitHub 반영·배포·메일 발송·계정 생성은 승인된 범위에서 진행합니다.
+

## 14. GitHub 연지 브랜치 업로드

- 사용자 요청: “깃허브에 업로드 해야해 연지 branch에 해줘.”에 따라 커밋·푸시 승인.
- 대상: `moondalyue/MOA`의 `연지` 브랜치. 원격 최신 커밋 `80a7ee3`을 확인하고 추적 브랜치로 전환했다. main을 수정·병합하거나 강제 푸시하지 않는다.
- 보존 대상: 원격의 `src/app/page.tsx`·`src/app/layout.tsx`는 다른 작업자가 만든 첫 화면이므로 보존했다. 이 첫 화면은 데모 폼이며 실제 Auth 화면은 `/signup`·`/login`이다. 첫 화면 연결·통합은 이번 업로드에 포함하지 않았다.
- 업로드 범위: 승인된 인증 소스·기존 입력 테스트·공개 환경 변수 예시·패키지와 lock·사용자 안내·이 계획이다. `.env.local`, 자동 생성 코드, 캐시·빌드 출력은 제외한다.
- 검증: 연지 최신 코드 위에서 `npm run check`와 입력 테스트 6개 통과. 비밀값 패턴 검사에서 발견된 DB URL은 계획의 가상 예시였다. 실제 비밀값은 포함하지 않는다. 빌드는 9절의 실행 환경 포트 제한으로 미완료이며 Vercel 배포·실제 계정 생성은 이번 Git 업로드로 완료되지 않는다.
- 실행 기록: 커밋·푸시를 진행하고 실제 완료 결과와 커밋은 사용자 응답으로 전달한다.
